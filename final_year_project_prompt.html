Final-Year Software Development

Project Specification Prompt

Use this prompt to generate a realistic project specification that meets the expected technical standard for a final-year software development project.

1. Start with your project idea

Create a project specification for this idea:

Project idea: [insert your idea]

Your specification should explain the main users, features, workflows, data, and technical approach.

2. Your project must

  • Use an established authentication solution such as ASP.NET Core Identity, Keycloak, Auth0, or equivalent.
  • Include user roles and an admin area for managing users.
  • Protect privileged routes and demonstrate token/session expiry.
  • Use a clear application architecture and persistent data storage.
  • Include meaningful business logic, not just simple CRUD screens.
  • Use APIs or external services where appropriate.
  • Demonstrate messaging using RabbitMQ, Azure Service Bus, or similar.
  • Include payments or subscriptions using Stripe or a similar API.
  • Allow users or administrators to view and manage subscription status, including cancellation and renewal where appropriate.
  • Handle payment/subscription events using appropriate mechanisms such as webhooks.
  • Include automated testing.
  • Use Git with regular, meaningful commits.
  • Be deployable outside your local development machine.
  • Include suitable technical documentation.
  • Consider usability, responsiveness, and accessibility.
  • Be fully understood by you so that you can explain your technical decisions.
Important: Do not propose a project built mainly with low-code, no-code, drag-and-drop, or UI-generation tools. Mobile frameworks such as React Native, Flutter, .NET MAUI, or Expo are acceptable only where you are writing and understanding the application code yourself.

3. Structure your specification

  1. Project Overview
  2. Users and Roles
  3. Core Features
  4. Security
  5. Architecture
  6. Data
  7. APIs / Integrations
  8. Messaging
  9. Payments / Subscriptions
  10. Testing
  11. Source Control
  12. Deployment
  13. UX / Accessibility
  14. Documentation
  15. Final Demonstration

4. Keep it realistic

Keep the scope achievable for a final-year project. The aim is to demonstrate sound software engineering, not unnecessary complexity.
